# 重写计划 · 综合仓人工单主线

日期：2026-10-29。依据 [QUALITY-GAP-vs-v0.3.md](QUALITY-GAP-vs-v0.3.md) 的结论 **C**。用户已确认整体重做，不沿旧 simapp 拼装路线打补丁。

本文件是下一条编码主线的范围。它不授权删除现有目录，也不把旧 `App.tsx` 拆文件当作重写。

## 1. 切片一句话

**综合仓、常温、单层、标准托盘、人工摆放：搭积木 → 对不可变布局推演 → 主四卡。**

客户不经过自动规划。第一条编码 PR 里不出现「帮我生成布局」、识图、成本对比、雷达、NSGA-II。

成功时，一个空白或矩形模板项目可以：

1. 从设备库放下 `ST-PAL-01`、收货月台、发货月台，用米制坐标改位置，撤销一步。
2. 保存得到服务端签发的 `layoutRevision`（浏览器不铸造修订号）。
3. 准备：派生货位与通道，权威校验。跨墙或没有可达 `accessNodeId` 时不能推演，并指向该实例。
4. 用一份明确的需求与资源跑 DES。四卡只渲染这次 run 的响应。
5. 改布局后再跑，旧跑次仍显示旧 `layoutRevision`，并标明已过期。

新代码放在工程根的 `next/`。旧的 `apps/`、`services/`、`shared/`、`contracts/`、`fixtures/`、`scripts/` 保持可运行，直到新切片自己通过 §6。删除旧树要另开 PR，本计划不包含删除。


`next/contracts` 是运行中的 schema。允许从现有 `contracts/schemas/v0.2` 与 `v0.3` **复制**本切片用到的文件作为起点（Snapshot 0.2、equip 0.2、LayoutDocument、Demand、OperatingProfile、ScenarioPackage、ValidationReport）。复制之后以 `next/contracts` 为准。旧目录继续服务旧脚本，两边不互相 import。

## 4. 最多三块并行，而且必须共用同一 schema 和同一金样

允许同时做的只有三块。三块读同一路径：

- Schema：`next/contracts/**`
- 金样：`next/fixtures/manual-wh/**`

任一字段变更先改这两处，再改 DES 或 UI。禁止 API、DES、UI 各自声明 `layoutRevision` 或四卡形状。

| 工作包 | 产出 | 合并条件 |
|---|---|---|
| 契约与夹具 | 子集 schema；一份可摆放的综合仓布局；一份非法跨墙布局；场景与资源；**先不要写四卡期望数字** | `next` 的夹具校验通过；短名类型 ID 被拒绝；Snapshot 版本不是 0.2 被拒绝 |
| DES | 读金样快照与场景，写出事件、库存账、四卡 | 守恒成立；快照字节不被修改；`expectedLayoutRevision` 不等则拒绝；非整托返回不支持而不是跳过并假装跑完；P95 按 05：n=0 为 null，n≥1 报 nearest-rank |
| UI | 库、画布、准备、四卡 | 页面上的每个数字都能在该次 run 的 JSON 里找到。无 run 时四卡区域没有数字 |

顺序仍然是一条线，写在同一个分支上：

1. Schema + 无 KPI 数字的夹具。
2. DES 对夹具跑出事件。
3. 仿真角色用事件**手工核对**吞吐、等待均值、P95、分资源利用率、瓶颈 TopN，把核对后的数字写回金样，并写上 `engineVersion`。核对前金样里禁止出现这五个数。
4. UI 只渲染 API 返回的这份结构。
5. 一个 PR 把 1–4 一起交给验收表。

不要五个功能分支。不要先做 UI 再让 DES 去凑界面上的数。

旧 `shared/python/simapp_des/engine.py` 可以打开对照事件阶段（到达、等资源、走路、取货、发运）。新包不引用它。旧引擎的 n<20 隐藏 P95、混合利用率、`FLOW_KIND_STUB` 不进入新包。

## 5. 本切片的合同子集

外层对象 `contractVersion = "0.3"`。推演快照 `schemaVersion = "0.2"`。类型 ID 用正式 ID（至少 `ST-PAL-01`、`IN-DOCK-01`、`OUT-DOCK-01`）。`layoutRevision` 不透明，只比较相等。

服务端签发修订。请求体里的 revision 若与已存修订冲突，返回 409，不覆盖。

本切片端点只这些：

| 方法 | 作用 |
|---|---|
| `POST /projects` | 建项目 |
| `POST /projects/{id}/facility-revisions` | 矩形场地与门 |
| `POST /layouts/{id}/revisions` | 保存布局，返回新修订 |
| `POST /layouts/{id}/prepare-jobs` | 派生 + 校验。计算在 worker 或后台任务；响应先给 jobId |
| `GET /jobs/{id}` | 准备或推演的状态 |
| `POST /simulation-jobs` | 绑定 `variant` 或布局修订 + 场景。未 `simulationReady` 则 409 |
| `GET /runs/{id}` | RunManifest、四卡、事件引用、轨迹引用、`layoutRevision` |

四卡字段：

- 吞吐：外部发运托当量 / 评价时长。无评价时长则 null。
- 等待：已完成任务的等待均值和 P95，附 `sampleCount`。无完成任务则均值和 P95 都是 null。
- 利用率：按资源类型分列，另可附明细。禁止只返回一个混合比作为唯一字段。
- 瓶颈：`topN` 至少包含界面要画的条目；无等待样本时 `topN` 为空数组，不用 0 秒冒充。

需求在本切片只接受 `flowKind = full_pallet`。其他作业类型返回 `UNSUPPORTED_SCENARIO`，运行不产生吞吐。

准备与推演的完成响应里带 `kpiFromUiDemo: false`。出现 true 则 UI 丢弃该响应并显示错误。

不在本切片的端点：规划、采用、价目、成本、比较、报告、识图、高级优化。

## 6. 验收表（未跑就写未跑）

编码 PR 必须贴出命令和原始结果。下表的「通过」只表示这一条观察到了。

| ID | 操作 | 必须观察到 |
|---|---|---|
| S-01 | 空白场地放下货架与两个月台，保存，准备，推演 | 请求序列里没有规划接口 |
| S-02 | 使用矩形模板走同一条路径 | 与空白路径共用保存/准备/推演，不另写一套状态 |
| S-03 | 把货架摆到穿墙的接入点 | 准备失败，正文含该实例 id，推演接口被拒绝 |
| S-04 | 通道窄于设备要求 | 准备失败，原因是窄通道 |
| S-05 | 同一快照、同一场景、同一资源连续跑两次 | 事件序列与四卡一致；快照修订字符串不变 |
| S-06 | 金样出库量使完成样本数小于 20（含默认小样本） | P95 仍按 nearest-rank 给出数值，或在 n=0 时为 null。禁止 n<20 整段省略 |
| S-07 | 零出库 | 等待均值与 P95 为 null，完成率 null，页面不显示 0 秒或 100% |
| S-08 | 两种资源类型（例如叉车与拣选；若切片只启用叉车，则叉车数量 ≥2 时仍按资源 id 分列） | 利用率不是一个无类型的混合数 |
| S-09 | 改布局并保存后查看上一次跑次 | 旧 run 的修订字符串与新修订不同，页面写明过期 |
| S-10 | 改出库托数后再看上一次跑次 | 同样过期。过期原因写需求，而不是要求用户先记「脏」 |
| S-11 | 刷新页面 | 最后一次已保存布局还在。未保存的草稿不显示成已保存 |
| S-12 | 金样四卡 | 与事件手工核对表一致，偏差为 0（整数托）或事先写明的舍入规则 |

S-06 是针对当前 `shared/python/simapp_des/kpi.py` 的回归：旧规则在样本不足 20 时不报 P95，而工作台默认就是 4 托。新金样必须包含这种小样本。

## 7. 明确排除

- 不大规模删除旧 simapp。
- 不把 `apps/web` 改成新 UI 的壳，也不在旧 `main.py` 上加 `if next`。
- 不把 `documents.ts` 的 demo 价目、48 托规划需求、默认开启的故障注入带进 `next/`。
- 不把 `03-UI原型` 的吞吐公式、假轨迹、localStorage 当金样。
- 不做 GLB、DXF、OCR、局部重排、多方案雷达。
- 金样里的托数、速度、处理秒只用于测试，不写进客户项目默认值。默认速度和处理时间若产品未给，界面显示「未填写」并拒绝推演，由仿真角色在夹具里给出**命名为测试**的数值。

## 8. 规模与风险

要新写的是：一份切片 schema、一组金样、一个事件引擎、一个只含上述端点的 API、一个分模块的工作台。不迁移 SQLite 工作台状态，不迁移规划器，不迁移成本。

主要风险：有人从 `App.tsx` 的 `onSimulate` / `onCostCompare` 把请求拼装拷进 `next/web`。验收时看 S-01 的请求序列和 S-06 的 P95。拷贝旧拼装的 PR 视为未完成。

旧引擎可当对照阅读。它不是依赖。
